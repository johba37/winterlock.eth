Quantum exposure check for Safe

Who could sign for your Safe if elliptic curves broke?

This page reads a Safe’s owners from the chain and from Safe’s Transaction Service, and shows how the Safe would stand against an attacker able to derive private keys from public keys: what it checked, what it found, and what it couldn’t check. It only reads: it never asks for a signature or a wallet.

How the check works

When a key is open to attack

An ECDSA key pairs a private key with a public key on an elliptic curve. Today nobody can work out the private key from the public one. A large enough quantum computer could, and so might new mathematics. No computer able to do this exists today, and nobody knows when one will.

An address is a hash of the public key, not the key itself. The public key becomes known when the key signs: a transaction, a Safe confirmation, a message. From any of its signatures, anyone can compute it. So the check asks, for each owner, whether its public key is known.

Each owner

The Safe

Exposed
At least as many owners as the threshold are exposed. An attacker able to derive private keys from public keys could move funds without anyone signing.
Exposed as owners sign
Fewer than that are exposed, but the quantum-vulnerable owners can reach the threshold. Each signature exposes a key.
Protected by hash-based owners
The quantum-vulnerable owners, with any the check can’t classify, are fewer than the threshold, and no module is enabled. Every set of signatures that reaches the threshold includes a hash-based owner.
Can’t tell
Owners the check can’t classify could make the difference, a module is enabled, or the contract isn’t made of Safe’s official contracts.

What it reads

From the network, through the RPC endpoint and at one block: the Safe’s proxy and singleton, owners, threshold, modules, guard and fallback handler; each owner’s code and transaction count; and the Safe’s balance of the native currency and of USDC and WETH where their addresses were checked against the issuer’s documentation.

From Safe’s Transaction Service, only when an owner is a key that hasn’t sent a transaction: the confirmations on the Safe’s transactions, executed or queued, and on its messages. At most five pages of 200 of each; a Safe nested in another is read the same way, up to three levels deep and ten Safes in all.

What it can’t see

    Where this comes from

    This check is part of Winterlock, which gives a Safe owners whose signatures rest on hash functions instead of elliptic curves. Winterlock is a research prototype on Sepolia, and its contracts are not audited.

    The check’s code is a small open library that other Safe tools can use, and this page is its static front end.

    Winterlock is an independent community initiative and is not affiliated with Safe or the Safe Ecosystem Foundation. This page loads no trackers, no external fonts and no scripts from other servers.
